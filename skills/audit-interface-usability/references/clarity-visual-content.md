# Clarity, visual structure, and content audit

Use this reference when reviewing screenshots, rendered UI, navigation, or interface copy.

## First-glance clarity

At a glance, determine whether the user can identify:

- what the screen or product is;
- where they are;
- what matters most;
- what they can do;
- what will happen next.

Flag unexplained terminology, ambiguous controls, hidden affordances, unclear clickability, and content that resembles advertising or decoration.

## Scanning and information scent

- Design review around scanning, not idealized linear reading.
- Check whether headings, labels, links, and first words carry the important meaning.
- Prefer specific destination or action labels over generic wording such as “Learn more” when context is insufficient.
- Break long content into descriptive sections and lists only where that improves retrieval.
- Remove instructions that compensate for an avoidably confusing design.
- Keep vocabulary stable for the same object and action.

## Visual hierarchy

- Confirm that visual importance matches task importance.
- Use size, weight, contrast, position, spacing, depth, and motion deliberately.
- Limit strong emphasis so the primary information and action remain distinctive.
- Check the screen with a squint or blur test: the intended groups and focal point should still read.
- Do not let visual polish mask task failures.

## Grouping and layout

- Group related elements by proximity and alignment before adding containers, borders, or shadows.
- Make spacing inside a group smaller than spacing between groups.
- Use whitespace to clarify relationships, not merely to create an aesthetic.
- Align repeated elements consistently and avoid accidental competing alignment axes.
- Treat grids as decision systems, not mandatory decoration.
- Check whether key content or actions fall below the initial viewport without sufficient cues.
- Test realistic long content, empty content, localization, and dynamic data.

## Navigation and orientation

- Keep global, local, utility, and contextual navigation roles distinguishable.
- Preserve a stable sense of location, hierarchy, and available escape routes.
- Use familiar names and destinations; do not mirror internal organization when it differs from user expectations.
- Check deep links, back behavior, modal exits, and return-to-context behavior.
- Avoid navigation models that scale poorly with the expected number of destinations.

## Controls, forms, and actions

- Make interactive elements identifiable without relying on color alone.
- Give one action primary emphasis only when it is genuinely the primary next step.
- Keep secondary and tertiary actions available without competing equally.
- Use action labels that describe the result.
- Preserve visible field labels; do not make placeholders carry label responsibility.
- Match the input control to the choice structure and expected value.
- Ask only for information needed at the current stage.
- Make destructive actions discoverable enough to use but not visually dominant by default.

## Aesthetic assessment

Treat aesthetics as part of perceived usability, trust, and emotion, but not as proof of actual usability. Report visual inconsistency when it weakens hierarchy, recognition, legibility, or confidence. Otherwise label it as craft improvement rather than usability severity.
