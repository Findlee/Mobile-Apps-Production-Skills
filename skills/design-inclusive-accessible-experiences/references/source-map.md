# Source map

Check publication dates and current versions before making implementation or conformance claims.

## Primary standards and pattern guidance

- [W3C Web Content Accessibility Guidelines](https://www.w3.org/WAI/standards-guidelines/wcag/) — current WCAG standard and supporting material.
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) — reference interaction patterns for accessible web widgets; examples are not a substitute for testing.
- [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility) — current Apple platform expectations.
- [Android accessibility guidance](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility) — current Android design guidance.

## Inclusive process

- [Microsoft Inclusive Design](https://inclusive.microsoft.design/) — methods for recognizing exclusion and designing with human diversity.
- Kat Holmes, *Mismatch: How Inclusion Shapes Design* — conceptual foundation for mismatched interactions, participation, and “solve for one, extend to many.”

## Source discipline

- Normative success criteria outrank summaries and third-party checklists.
- Platform guidance supplements rather than replaces the applicable standard.
- Local regulation, procurement rules, and organizational targets may add requirements.
- Cite exact version, target level, environment, scope, and evidence date in formal reports.
