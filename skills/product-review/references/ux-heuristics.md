# UX Heuristic Review Reference

Reviewed: 2026-08-08
Primary source: Nielsen Norman Group

## 10 usability heuristics

1. Visibility of system status
2. Match between system and the real world
3. User control and freedom
4. Consistency and standards
5. Error prevention
6. Recognition rather than recall
7. Flexibility and efficiency of use
8. Aesthetic and minimalist design
9. Help users recognize, diagnose, and recover from errors
10. Help and documentation

## How to apply in product-review

A heuristic evaluation is expert inspection.

Do not call a heuristic issue a proven user problem unless supported by user or behavioral evidence.

For each issue record:

- user/task/device;
- screen/state;
- heuristic;
- observed design behavior;
- likely user consequence;
- severity relative to task criticality;
- recommendation;
- confidence.

## Independent evaluation caveat

NN/g recommends multiple independent evaluators because one evaluator will miss issues and group discussion can bias observations.

A single AI agent must not pretend to be several independent human evaluators.

It may apply multiple analytical lenses, but report the result as one expert review.

## Scope protocol

Narrow scope when useful by:

- one task;
- one app section;
- one user group;
- one device type.

First understand the flow, then inspect for issues.

## Product interpretation

Heuristics are useful for:

- finding obvious interaction friction;
- finding status/feedback gaps;
- identifying consistency problems;
- identifying error/recovery weaknesses;
- cognitive-load reduction;
- simplifying crowded interfaces.

They are not sufficient for:

- validating customer demand;
- selecting a product strategy;
- estimating prevalence;
- proving retention impact;
- proving business value.
