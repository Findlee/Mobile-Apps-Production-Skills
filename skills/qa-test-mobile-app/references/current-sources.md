# Current primary sources for mobile testing

These are living sources. When a recommendation depends on a current platform, store, security, or accessibility rule, browse the relevant official page, state the version or access date, and cite it. Prefer the project's declared target versions over the newest platform behavior.

## Cross-platform

- OWASP Mobile Application Security project, MASVS and MASTG: https://mas.owasp.org/
- W3C Web Content Accessibility Guidelines overview: https://www.w3.org/WAI/standards-guidelines/wcag/
- ISO/IEC 25010:2023 product quality model: https://www.iso.org/standard/78176.html

## Apple platforms

- App Review Guidelines: https://developer.apple.com/app-store/review/guidelines/
- Accessibility testing for apps: https://developer.apple.com/documentation/accessibility/performing-accessibility-testing-for-your-app
- XCTest documentation: https://developer.apple.com/documentation/xctest
- MetricKit documentation: https://developer.apple.com/documentation/metrickit

## Android

- App quality guidance: https://developer.android.com/quality
- Test apps on Android: https://developer.android.com/training/testing
- Accessibility testing: https://developer.android.com/guide/topics/ui/accessibility/testing
- App performance guidance: https://developer.android.com/topic/performance

## Currency rules

- Do not copy volatile store deadlines, SDK requirements, OS support dates, or security category versions into the core workflow.
- Verify from official pages at the time of use.
- If an official source and a book disagree, retain the book's durable testing principle but follow the current official platform fact.
- Label recommendations that are judgment rather than a documented requirement.
