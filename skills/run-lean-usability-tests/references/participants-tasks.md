# Participants and tasks

Use this reference to recruit for meaningful differences and write neutral scenarios.

## Participant criteria

Recruit around behavior and context that can change the result:

- relevant activity or responsibility;
- novice, occasional, frequent, or expert experience;
- decision authority or collaboration role;
- device, environment, connectivity, or input method;
- language and domain vocabulary;
- accessibility needs relevant to the product;
- prior use of the product or a competing workflow.

Avoid narrow demographic filters without a causal design reason. Recruit loosely and interpret differences explicitly when exact matches are difficult.

## Sample matrix

For heterogeneous audiences, create a coverage table:

```text
Participant | Role/activity | Experience | Device/input | Access need | Critical task coverage
```

Do not claim representation beyond the people actually studied.

## Task selection

Prioritize:

- the core value or critical path;
- high-consequence decisions;
- common support or failure areas;
- new or disputed designs;
- changed behavior that may break an established model;
- recovery when it materially affects success.

Choose enough tasks for the session while leaving time for natural exploration and follow-up.

## Task wording

A useful task provides:

- a believable motivation;
- the outcome to achieve;
- necessary data the participant would otherwise know;
- a clear stopping point.

It does not reveal:

- the button, menu, label, or path;
- the feature name being tested;
- a preferred strategy;
- an evaluation such as “easy” or “obvious.”

Prefer personalizable details when safe: “Choose a book you would want to buy” can create more realistic engagement than an arbitrary item.

## Task template

```text
Scenario: [Why the participant is here]
Goal: [Outcome, without interface instructions]
Provided information: [Safe account, values, or constraints]
Success evidence: [Observable completion state]
Stopping rule: [Success, time, unrecoverable block, or distress]
Follow-up: [Neutral question asked after behavior]
```

## Order and bias

- Begin with orientation or a first-impression prompt when relevant.
- Avoid teaching later tasks through earlier wording.
- Counterbalance order when learning from one task would materially bias another.
- Keep destructive or privacy-sensitive tasks in safe environments.
- Record when moderator help changes subsequent behavior.

## Screening

Use behavior-based screening questions that do not reveal the desired answer. Avoid collecting unnecessary personal data. Separate scheduling information from research data when possible.
